# الويب — نافذة تقييم المنتج ومتوسط التقييم

> **أرسلوا هذا الملف لفريق الويب.**  
> **آخر تحديث:** 27 أيلول 2026  
> Base: `/api/user` + `Accept-Language: ar|en`  
> **الباك جاهز بعد `git pull`**

نافذة التقييم لازم تتسكرول لحد زر الإرسال، ومتوسط المنتج يتحدث بعد الحفظ.  
لا تخلّوا `rating` ثابت على `0`.

---

## 1) نافذة التقييم

النافذة أطول من الشاشة. الصفحة نفسها ما تتسكرول والنافذة مفتوحة، فالتمرير يكون **داخل النافذة**.

| المطلوب | |
|---------|--|
| ارتفاع النافذة | حد أقصى حوالي `90vh` |
| المحتوى | `overflow-y: auto` |
| زر الإرسال و«لاحقاً» | يبقيان ظاهرين أسفل النافذة (`sticky`) |
| الإغلاق | زر الإغلاق يبقى فوق المحتوى |

إذا النافذة انقصّت عند «أضف صورة» وما طلع زر الإرسال، التمرير داخلها مو شغال.

---

## 2) بعد الإرسال

`POST /api/user/ratings` (مستخدم مسجّل).

| الحقل | القيمة |
|--------|--------|
| `type` | `product` |
| `rateable_id` | `id` المنتج |
| `rating` | عدد صحيح من 1 إلى 5 |
| `comment` | اختياري |
| `order_id` | اختياري |
| `image` | اختياري، صورة، حد أقصى 2MB |

`rateable_id` هو معرف المنتج، مو `shop_product_variant_id`.

بعد نجاح الطلب أعيدوا جلب:

- تفاصيل المنتج `GET /api/user/products/{id}`
- قائمة المنتجات إذا الكرت ظاهر
- تقييمات المنتج `GET /api/user/ratings?rateable_type=product&rateable_id={id}`

اعرضوا `rating` و `rating_breakdown` من الرد الجديد. لا تبقوا على القيمة القديمة.

---

## 3) شو يرجّع المنتج

من تفاصيل المنتج وقائمة المنتجات:

```json
{
  "id": 15,
  "rating": 5,
  "rating_breakdown": {
    "1": 0,
    "2": 0,
    "3": 0,
    "4": 0,
    "5": 1
  }
}
```

| الحقل | المعنى |
|--------|--------|
| `rating` | متوسط التقييم من 1 إلى 5، منزلة عشرية واحدة. `0` يعني ما في تقييمات. |
| `rating_breakdown` | عدد التقييمات لكل نجمة. موجود في تفاصيل المنتج. |

تقييم واحد بخمس نجوم يخلّي `rating` = `5`، مو `0`.

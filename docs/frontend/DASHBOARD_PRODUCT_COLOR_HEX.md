# الداشبورد — حفظ لون المنتج من جدول `colors`

> **أرسلوا هذا الملف لفريق الداشبورد.**  
> **آخر تحديث:** 28 تشرين الأول 2026  
> Base: `/api/admin` + Admin token  
> **الباك يرفض النص الحر على صفة اللون بعد `git pull`**  
> الويب: [`WEB_PRODUCT_COLOR_HEX.md`](./WEB_PRODUCT_COLOR_HEX.md)  
> Flutter: [`FLUTTER_PRODUCT_COLOR_HEX.md`](./FLUTTER_PRODUCT_COLOR_HEX.md)

المشكلة ليست في العرض. الموقع يلوّن من `hex` فقط، وهذا تأكد على منتجين حيين:

- كريم الأساس 68: الخيار `141` اسمه `101` و`hex = #110011`، والخيار `142` اسمه `201` و`hex = #220011`. الدائرة تلونت، والفلتر صفّى بالـ id.
- ليب غلوس 95: الخيار `160` اسمه `2` و`hex = null`، والخيار `161` اسمه `7` و`hex = null`. نفس الشيء في `shop_variants` `208` و`209`. الدائرة رمادية `rgb(161, 161, 170)`. إعادة حفظ المنتج بلا تغيير قيمة الصفة ما بتملأ `hex`.

الحفظ كان يسمح بدرجة بلا `color_id`، فيرجع `hex: null`. الإصلاح على **قيمة صفة الفئة**، مرة واحدة لكل الكتالوج.  
جدول `colors` هو التدرج: الاسم للعرض، و`hex` للون. إذا الدرجة غير موجودة تُضاف هناك أولاً مع `hex` مثل `#3E434A`. أرقام `2` و`7` ليست لوحة جاهزة.

## 1) القاعدة

قيمة صفة اللون تُحفظ بـ `color_id = colors.id`.

من دون هذا الاختيار ينحفظ النص فقط، مثل `2` أو `7`، ورد المستخدم يرجع `hex: null` والدائرة تبقى رمادية.

صفة اللون هي واحدة من:

- `type = color`
- أو اسم الصفة `Color` / `اللون` (حتى لو `type` محفوظ `square`)

عندها:

- إذا أُرسلت `values` وفيها صف بلا `color_id`، الحفظ يُرفض (`values.N.color_id`).
- إغفال `values` أو إرسالها `[]` عند **إنشاء** الصفة يبقى يربط لوحة `colors` كاملة، وكل صف فيها معه `color_id`.
- ترك `values` خارج طلب **التعديل** لا يعيد كتابة القيم الحالية.

قائمة الداشبورد الملونة (اختيار القيمة على المنتج) تعرض فقط القيم المربوطة بسجل فيه `hex` صالح. القيمة النصية بلا سجل لا تظهر كدائرة.

`options[].id` في رد المستخدم يبقى رقم قيمة الصفة. `shop_variants[].id` يبقى رقم السلة. `type` يبقى كما حُفظ. التطبيق ما يرسل `color_id` وما يلوّن من الاسم.

## 2) إضافة تدرج ناقص

فورم المنتج يختار قيمة صفة جاهزة، ولا ينشئ لوناً.

إذا التدرج غير موجود في القائمة، يُضاف **مرة واحدة** في جدول `colors` مع `hex`، ثم تُربط به قيمة الصفة، وبعدها يُختار من فورم المنتج.

أرقام `2` و`7` (مثل ملمع الشفاه، منتج 95) ليست ضمن لوحة جاهزة. تُضاف أولاً كصفوف في `colors` مع `hex`، ثم تُربط قيم الصفة بها.

```http
POST /api/admin/colors
```

```json
{
  "name": { "en": "Charcoal", "ar": "فحمي" },
  "hex": "#3E434A",
  "is_active": true
}
```

`hex` مطلوب، بصيغة `#RRGGBB` (يُحفظ أحرف كبيرة)، وفريد في الجدول. الاسم للعرض فقط.

إذا سجل اللون نفسه بلا `hex`، الدائرة تبقى رمادية حتى يُملأ الحقل في `colors`.

## 3) حفظ قيمة الصفة

```http
POST /api/admin/category-attributes
PUT  /api/admin/category-attributes/{id}
```

```json
{
  "category_id": 8,
  "name": { "en": "Color", "ar": "اللون" },
  "type": "color",
  "values": [{
    "id": 160,
    "name": { "en": "2", "ar": "2" },
    "color_id": 31
  }]
}
```

- `color_id` رقم صف في `colors`، مو رقم قيمة الصفة.
- عند التعديل أرسلوا `values[].id` حتى يبقى نفس الصف على المتغيّرات.
- `GET /api/admin/category-attributes` و`GET /api/admin/category-attributes/{id}` يرجعان `color_id` و`hex` لصفة اللون، حتى لو الاسم `Color` / `اللون` والنوع المحفوظ `square`.

## 4) فورم المنتج

1. اختاروا صفة اللون.
2. القائمة تعرض القيم المربوطة بسجل فيه `hex` فقط.
3. القيمة المختارة هي رقم صفة (`attribute value id`)، وتُحفظ على المتغيّر كما هي.
4. إعادة حفظ المنتج من دون تغيير قيمة الصفة لا تلوّن شيئاً. منتج 95 يبقى رمادياً لأن `2` و`7` نص بلا سجل في `colors`.

---

## 5) القيم القديمة

القيم الحالية بلا `color_id` تُربط بسجل موجود، أو تُعاد من الداشبورد باختيار من القائمة.

لا تُضاف قوائم أسماء جديدة في الكود لباقي الكتالوج. قائمة المناكير الثلاثة عشر كانت ترقيعاً لأسماء ذلك المنتج فقط، وخلّصت درجاته. لا تُكرَّر.

---

## 6) شو يشوف المستخدم

الرد جاهز عندما يكون الربط موجوداً. `GET /api/user/products/{id}` و`GET /api/user/categories/{id}/attributes` ينسخان `colors.hex` إلى:

- `attributes_map[].options[].hex`
- `shop_variants[].attributes[].hex` لنفس رقم الخيار
- `values[].hex` في صفات الفئة

`Accept-Language` يغيّر الاسم فقط. `hex` ثابت.
